# 禁令三類分流 (Prohibition Triage)

**何時讀本文**：技能內含「不要／切勿／嚴禁／絕對禁止／never／must not」等禁令語句，需要改寫、移動或審查時。

---

## 1. 三類定義

| 類別 | 定義 | 歸宿 |
| :--- | :--- | :--- |
| **A_CRITIC_RULE** | 抽象的品質要求（不可空泛、不可平庸、勿捏造、勿混淆概念） | Actor 端改寫成正向規格；原禁令轉成 Critic 可檢查的斷言 |
| **B_CODE_ENFORCED** | 不可逆或破壞性動作（刪除輸出、覆寫 archive 原檔、遞迴刪除、改動狀態快照） | 主約保留明載，並由前置程式碼守門阻擋；附阻擋測試 |
| **C_ROUTER_EXCLUSION** | 任務排他邊界（這個技能不處理什麼） | 保留在 description 的 `Do NOT use for...` |

---

## 2. 判定流程

對每一條禁令依序問：

1. **違反後能否事後復原？** 不能 -> **B**。
2. **是否描述「這個技能不該被用來做什麼任務」？** 是 -> **C**。
3. **是否為品質、風格、內容層面的要求，且違反後可由審查退件修正？** 是 -> **A**。
4. **以上都無法確定** -> 歸 **B**，並列入待確認清單交使用者。

把 B 誤判成 A 的代價最高（事後審查擋不住已發生的破壞），所以不確定時往 B 歸。

---

## 3. 改寫範例

| 原句 | 類別 | 處理 |
| :--- | :--- | :--- |
| 切勿隨意捏造欄位名稱 | A | Actor：「欄位名稱取自 `template.json`」；Critic 斷言：輸出鍵名皆存在於範本 |
| 不要把時間軸單位弄混 | A | Actor：「時間一律以毫秒表示」；Critic 斷言：所有時間欄位為整數毫秒 |
| 嚴禁遞迴刪除 `_outputs` | B | 主約保留；刪除一律呼叫守門模組，並有測試證明該路徑被擋下 |
| 不得修改 archive 原檔 | B | 主約保留；以唯讀保護或路徑檢查強制 |
| 不用於單行程式碼微調 | C | 留在 description 的 `Do NOT use for...` |

---

## 4. B 類守門的最低要求

1. **有實體守門**：例如共用的 `safe_delete(path, output_root)`，解析真實路徑後確認落在宣告的 `output_root` 內。
2. **有阻擋測試**：至少涵蓋工作區根目錄、`_outputs` 本身、`output_root` 外部路徑、未解析的變數，結果必須全部被擋下。
3. **主約有指針**：B 類條目寫明「由哪個守門模組強制」，不只是文字宣告。

---

## 5. 矩陣格式 (`all_prohibitions.json`)

```json
{
  "skill": "example-skill",
  "source_commit": "<原始版本 commit hash>",
  "items": [
    {
      "id": "P001",
      "file": "SKILL.md",
      "line": 42,
      "original": "（原文）",
      "class": "A_CRITIC_RULE",
      "destination": "critic_assertion:keys_exist_in_template",
      "needs_user_confirmation": false
    }
  ]
}
```

**完整性檢查**：每一條原始禁令都有 `class` 與 `destination`；未分配數量為 0；`B_CODE_ENFORCED` 項目都有對應守門與測試。

---

## 6. 驗收看實質，不看詞數

只統計「不要／切勿／嚴禁」出現次數不能證明品質：把「不要刪除 X」換成「務必保留 X」也能讓次數歸零，但約束的強度沒有改變。驗收以矩陣歸宿、B 類阻擋測試與行為測試為準。

初分類可由 LLM 做，腳本負責檢查完整性；B 類條目由人工抽驗。
